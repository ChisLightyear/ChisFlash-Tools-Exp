## 入口

合卡器：烧录卡模式选择“NES | CHISBOY专用卡（MBCX）”，进入独立嵌入工作区。上位机：选既有 Beggar / MAX-MBCX 烧录器，物理模式 GB，再从烧录方案选择 FC。底层仍为 GB 总线，不是实体 FC 烧录卡协议。

2.018 起：进入 NES 工作区后，导入 ROM 即可点击“烧录 FC 卡”，首次烧录会自动读取 NOR 与目录，再显示写入/转换确认；不需要在该工作区先手动扫描。全 FF 空白 MBCX 可直接建立 FC 配置，已有 FC 卡会先合并保留原游戏。导入整卡 BIN 仍按替换列表处理。

工作区支持 NES / ZIP 导入、改名、勾选、上移/下移、删除、BIN 生成与导入。上位机另支持卡内扫描及烧录。扫描保留待导入文件；导入整卡 BIN 后扫描不会把待写镜像列表丢掉。旧 GB/GBA 工作区不共用 FC 菜单/补丁流程；从 FC 返回后，卡上旧分析必须重新扫描。

## ROM 与 SRAM 粒度

- ROM 银行 16 KiB；游戏区从 0x100000 开始，最多 99 项、32 MiB 寻址。文件头/trainer/ROM 内容不改，只补银行尾 FF。
- 存档 SRAM 银行 8 KiB，512 KiB 卡共 64 个：0..59 独立（480 KiB），60..63 共享（32 KiB），沿用现有 MBCX 布局。
- 确认无 PRG 工作/保存 RAM 的条目不分配，RAM 数为 0，银行表全 FF。
- 有 RAM 且带电池：按实际所需字节数向上取整 8 KiB，分配独立银行，已有有效独立映射优先保留。
- 有 RAM 且不带电池：按实际尺寸使用共享银行，不按游戏数重复消耗独立区。
- 独立空间不足明确拒绝，不会默默改共享。普通 CHR 工作 RAM 不算卡带存档；PC 保留 CHR RAM/NVRAM 元数据，实际运行能力由所装核心决定。
- **PC 规划并写目录映射，不主动修改卡带 SRAM；02 0031 起已接通按目录银行映射的游戏 WRAM。**

## Mesen 信息补全

来源：Mesen2 上游源码仓库，提交 b9fa69ddc6d0a331fb103fdb5eef6904305703c2。使用 UI/Dependencies/MesenNesDB.txt 的数据，保存在 Fc/MesenNesDB.csv，作为资源嵌入两端 EXE。数据库本身注明生成于 2022-07-21，不声称是在线最新库。源码许可原文保留于 Fc/Mesen-LICENSE。

参照 iNesLoader.cpp、GameDatabase::UpdateRomData、NesHeader 与 BaseMapper 的规则：

1. NES 2.0 优先使用明确的 RAM/NVRAM 字段，明确 0 不擅自加 8 KiB。
2. iNES 使用去除 16 B 文件头与可选 512 B trainer 后剩余内容的 CRC32 查表，与 Mesen 的 PRG+CHR CRC 范围一致。
3. 数据库已确认记录（submapper 字段非空）可把 RAM 改为 0，并覆盖电池信息；未确认记录只补正数 RAM、电池位取 OR。
4. 剩余未知 RAM 使用所支持 Mapper 的 Mesen 默认值，明确显示“推定”；并不是所有 iNES 都被当作肯定有独立存档。
5. ROM 本体保持原样。数据库指出 Mapper/submapper/几何与当前 loader 将解析的头不等价时，列为不兼容并要求修复头；不会在 PC 上改个显示值就假装 FPGA 已按修正配置运行。Mapper 2/3 的默认带总线冲突路径与显式 submapper 2 视为等价。

CRC 是用户要求的 ROM 数据库识别，不是运行固件 hash 检查。列表显示 Mapper、PRG/CHR、RAM、分配容量、电池、独立/共享、具体银行及信息来源。

## 目录兼容

配置 0x020000，目录 0x040000，条目从 0x040040 开始，每条 128 B。新文件同时保留第 7 字节的旧 FC 标记 1，并在第 8..9 字节写标准版本 1；配置 +32 写 FC02、+36 元数据版本 1、+37=13 表示 SRAM 银行 2^13 B。当前已交付 FC loader 可继续读取。

条目：+4 ROM 银行，+8 分配银行数，+10 存档银行数，+11=FC，+12 实际电池标志，+13=valid+准确长度标志；+14..109 UTF-16LE（空本地名称、标题、终止符）；+110..117 SRAM 银行表；+118 原 NES 字节数；+122 实际存档映射字节数；+126 表示是否使用 Mesen 元数据。未知字符在当前 02 上仍显示问号。

旧 Python FC 镜像仍可读取。GBC 扫描遇到 FC 标记会拒绝套用 GB 头校验/菜单修复；GB 写入入口再次检查，避免旧分析状态误刷 FC 卡。

## 烧录与取消

NOR 型号名称仅供显示，不作为可用名单；实际容量与写保护继续检查。写入前核对端口、NOR 身份、容量、扇区与已扫描目录。先读出所有受影响扇区，保留邻接 ROM 数据；再临时隐藏所有会被擦写的条目，写 ROM，最后提交最终目录。改名/排序/删除通常只更新目录，删除空间供后续复用。

非 FC（含空白卡）或已损坏目录需显式转换确认。烧录前自动扫描只读，不执行擦写；扫描后重新按实际容量验证列表。芯片未识别或写保护会显示明确原因并禁止写入。取消/写入失败不报告完成，并失效旧快照；涉及原卡条目的修改必须重新扫描，失败的扫描也不会保留旧的可写快照。扇区操作增加有界取消；软件未实际连接串口执行这些流程。离线导出写临时文件，全部成功且未取消才替换目标。
