# GBA 菜单行和游戏行

上位机2.046 r9，沿用MBC列表的操作逻辑，保留r5的窗口区域、工具栏、表格和日志布局。

2.046 r10补齐单卡禁用提示：菜单未添加时，游戏1下方显示灰色“游戏2／不可用／添加菜单后开放”，代表游戏2及后续游戏不能使用。选中该行会禁用导入、替换、移除及导出，双击或拖入也不会修改游戏1。添加菜单后该行开放为可添加游戏；移除菜单或清空后恢复禁用提示。

## 工作区

- 菜单在首行，游戏从游戏1开始。无菜单时仅游戏1可用，从地址0写入原ROM。地址0已有有效游戏头时显示其标题和游戏代码，实际ROM长度未确定时明确标注。
- 双击菜单行或选中后导入，可以使用所选的内置菜单，也可以导入兼容菜单文件。添加菜单形成合卡草稿，保留游戏1并开放末尾的添加游戏行。
- 选中游戏行导入或拖入文件执行替换，选中末尾空行可以添加游戏。菜单行不进入游戏目录、排序、容量或存档计算。
- 多个游戏时须先移除游戏2及后面的游戏，才可移除菜单。只保留游戏1时移除菜单回到单卡草稿。清空将菜单和游戏从本地工作区移除，保留空的菜单和游戏1入口。
- 扫描已有合卡时显示卡内菜单与目录游戏。重新扫描按实际数据重建；仅刷新同一扫描结果的界面时保留草稿。碎片表缺少有效目录时标注异常，不猜测单卡。

## 写入

列表操作只准备本地内容。单卡写入从0开始，保留原文件字节，不自动安装菜单或打补丁。已有合卡移除菜单后保留原游戏映射，实际烧录时先读取游戏，再写到0；界面中的地址变化不是提前搬动数据。

新建合卡沿用配套合卡器，保留当前原始单游戏时在烧录确认窗口指定读取长度。所有游戏完整准备成功才开始擦写，游戏区先写，前4MiB菜单和目录最后提交。已有合卡的菜单替换、游戏更新、存档布局沿用原流程。保留只读、实际容量、布局和CHM1硬件识别限制，不恢复已取消的GBA写后读回比较。

GBA 1.0V和GB/GBC继续使用各自专用流程。

## 验证

使用离线数据和实际Form1控件验证菜单行、单卡判断、导入替换、添加游戏、移除菜单、保留源映射、目录异常、标题编辑、排序、只读及硬件限制。合卡镜像覆盖普通、CHM1、有电池与免电、水线布局，验证写入顺序。另运行单游戏扫描、GBC选型回归，并对照r5的14个原控件位置、尺寸、可见性与父容器。

本次未访问串口或擦写实卡；界面预览使用模拟端口与离线头部数据。
